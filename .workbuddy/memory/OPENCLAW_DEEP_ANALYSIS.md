# OpenClaw 开源项目深度技术分析

## 1. 项目概述

OpenClaw（原ClawdBot）是一个**自托管的多渠道AI Agent网关**，采用MIT协议开源。其核心目标是让AI模型能够通过20多种聊天工具（如微信、Telegram、Discord等）作为接口，安全地操作用户的操作系统、执行命令、管理文件和调用API。

### 1.1 核心特性

| 特性 | 说明 |
|------|------|
| **本地优先架构** | 数据始终存储在本地设备，用户完全控制数据隐私 |
| **多渠道支持** | 统一接入微信、飞书、Telegram、Discord等20+平台 |
| **Agent编排** | 支持多智能体协作与任务编排 |
| **工具系统** | 52个内置技能，可扩展自定义工具 |
| **Docker沙箱** | 命令默认在受限的Docker容器中执行 |
| **上下文压缩** | 自动调用LLM对历史进行摘要，释放上下文空间 |
| **故障转移** | 主LLM服务不可用时自动切换到备选模型 |

### 2.2 核心组件详解

#### 2.2.1 Gateway 网关层

**职责**：作为系统的门户，负责与各种聊天渠道对接，处理消息的入口和出口。

| 组件 | 功能 |
|------|------|
| **Channel Dock** | 通过统一的适配器抽象不同聊天渠道的差异，将所有消息标准化 |
| **Routing Engine** | 根据消息来源（渠道、账号、群组等）智能地将消息路由到指定的Agent |
| **Session Manager** | 管理会话状态，支持主会话、私聊、群聊等不同会话类型的权限隔离 |
| **Plugin System** | 支持渠道插件、记忆插件、工具插件、模型提供商插件的扩展 |

#### 2.2.2 Agent 运行时层

**职责**：作为AI的"大脑"，负责处理逻辑、调用工具、与LLM交互。

**核心机制**：

1. **动态System Prompt构建**
   - 每次请求都会动态组装提示词
   - 包含：身份声明、工具列表、安全宪章、运行时上下文
   - 工具定义自动注入，仅加载当前对话所需的技能

2. **Agent运行循环（核心执行引擎）**
   ```
   接收用户消息 → 加载历史 → 构建上下文 → 调用LLM
        ↑                                      │
        └──────── 返回结果给用户 ← 生成回复 ←─┘
                          │
                    需要工具调用?
                          │
        ┌─────────────────┴─────────────────┐
        ▼                                   ▼
   执行工具调用 ←────────────────────── 解析工具请求
   ```

3. **上下文压缩**
   - 当对话历史超出LLM上下文限制时
   - 自动调用LLM对历史进行摘要
   - 释放空间以继续对话

4. **故障转移**
   - 当主LLM服务不可用时
   - 自动切换到备选模型
   - 保证服务高可用

#### 2.2.3 能力层

| 组件 | 说明 |
|------|------|
| **Sandbox（Docker沙箱）** | 命令默认在只读的Docker容器中执行，与主机隔离 |
| **Skills（52个技能）** | 可插拔技能系统，本质是给AI的Markdown格式"说明书" |
| **Memory（向量记忆）** | 基于向量数据库实现，允许Agent跨会话记住信息 |

## 3. 核心安全机制

OpenClaw设计了**三重防线**，确保AI代理在拥有强大能力的同时不会失控：

### 3.1 第一层：Docker沙箱隔离
- 命令默认在受限的Docker容器内执行
- 文件系统为只读
- 仅挂载必要的工作目录
- 清洗环境变量

### 3.2 第二层：命令白名单
- 不是简单的字符串匹配
- 对命令进行深度解析（管道、重定向）
- 验证二进制文件路径
- 检测Base64编码等混淆手段

### 3.3 第三层：人工审批
- 对于白名单之外的命令
- 根据配置向用户发起审批请求
- 用户可选择"单次允许"、"始终允许"或"拒绝"

## 5. 工作流程详解

### 5.1 消息处理流程

```
1. 用户通过聊天渠道发送消息
        │
        ▼
2. Channel Dock 接收并标准化消息
        │
        ▼
3. 路由引擎根据配置将消息路由到对应Agent
        │
        ▼
4. Agent运行时加载会话历史和上下文
        │
        ▼
5. 动态构建System Prompt（包含可用工具）
        │
        ▼
6. 调用LLM进行推理
        │
        ├── 生成文本回复 → 直接返回给用户
        │
        └── 请求工具调用 → 执行工具 → 将结果返回LLM → 生成回复
```

### 5.2 Agent Loop 详细流程

```
┌─────────────────────────────────────────────────────────────┐
│                      Agent Loop                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 接收用户输入                                            │
│       │                                                     │
│       ▼                                                     │
│  2. 加载历史消息 + System Prompt                            │
│       │                                                     │
│       ▼                                                     │
│  3. 调用 LLM.generate()                                     │
│       │                                                     │
│       ├── 返回文本 → 8. 返回给用户                          │
│       │                                                     │
│       └── 返回工具调用 → 4. 解析工具调用                      │
│                             │                               │
│                             ▼                               │
│                       5. 执行工具                           │
│                             │                               │
│                             ▼                               │
│                       6. 获取工具结果                        │
│                             │                               │
│                             ▼                               │
│                       7. 将结果加入上下文                    │
│                             │                               │
│                             └──────→ 3. 再次调用LLM          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 6. 核心设计哲学

| 哲学 | 说明 |
|------|------|
| **自主权** | 数据私有，用户完全控制部署位置、消息路由、工具权限和会话隔离 |
| **开放性** | 高度可扩展的插件系统，无需修改核心代码即可添加新功能 |
| **安全性** | 三层防线（沙箱隔离+命令白名单+人工审批）确保AI不会失控 |
